## [2.0.0] - 2026-07-28
### Added
- **`DOCKERFILE_PATH`** optional input (default `'Dockerfile'`) — same name, semantics and default as the input of the same name in `action-dockerization`. Used to locate the Dockerfile this action parses for ports, networks and volumes.
- **`COMPOSE_NAME`** optional input — base name for the generated Docker Compose file (`<COMPOSE_NAME>.yml`). Defaults to the repository name when omitted.
- `scripts/dockerfile_config.sh` — validates `DOCKERFILE_PATH` exists and resolves `COMPOSE_FILE_NAME`.
- `scripts/port_formatter.sh`, `scripts/net_formatter.sh`, `scripts/volume_formatter.sh` — parse `EXPOSE`/`# TO`, `# NETWORK` and `# VOLUME` comments from the Dockerfile to produce `COMPOSE_PORTS`, `COMPOSE_NETWORKS` and `COMPOSE_VOLUMES`.

### Changed
- **BREAKING:** Docker Compose metadata (ports, networks, volumes, compose file name) is now generated by this action itself instead of being received from `action-dockerization`. As of `action-dockerization` v3.0.0, that action no longer produces this metadata — generating it is a deployment concern, not a build concern.
- Scope of this action now matches its description: given a Dockerfile and a built image, it fully owns deciding and assembling the Docker Compose deployment.

### Removed
- **BREAKING:** `COMPOSE_PORTS`, `COMPOSE_NETWORKS`, `COMPOSE_VOLUMES`, `COMPOSE_FILE_NAME` inputs — these are no longer accepted as inputs; they're derived internally from `DOCKERFILE_PATH` and `COMPOSE_NAME`.

### Migration Guide (v1.x → v2.0.0)

1. Remove `COMPOSE_PORTS`, `COMPOSE_NETWORKS`, `COMPOSE_VOLUMES`, `COMPOSE_FILE_NAME` from your `with:` block — they are no longer accepted.
2. If you rely on the Dockerfile comment syntax (`# TO`, `# NETWORK`, `# VOLUME`) to configure your deployment, add `DOCKERFILE_PATH` pointing to the same Dockerfile you pass to `action-dockerization` (defaults to `Dockerfile` if omitted).
3. If you previously set `COMPOSE_NAME` on `action-dockerization` (removed there in v3.0.0), pass it to `action-deployer` instead — note the compose file name no longer has an environment suffix, it's just `<COMPOSE_NAME>.yml`.
4. Ensure `actions/checkout` runs before this action in the same job, since it now reads the Dockerfile from the repository.
5. Bump to `@v2.0.0`.

## [1.0.3] - 2025-02-02
### Changed
- Improved logging throughout the action with concise, essential debug information
- Enhanced error messages with clear failure points and validation feedback
- Added input validation step to catch missing parameters early
- Streamlined deployment logs to show progress without excessive verbosity

### Fixed
- Better error handling in SSH setup step with explicit failure messages
- Improved SCP and SSH error detection for clearer troubleshooting
- Enhanced script execution with proper exit codes on failures

### Documentation
- Added better visibility of deployment parameters at action start
- Improved log structure with progress indicators (✅) for successful steps

## [1.0.2] - 2025-10-16
### Changed
- Made `COMPOSE_PORTS` parameter optional - containers can now be deployed without port mappings
- Made `COMPOSE_NETWORKS` parameter optional - containers can use Docker's default networking if not specified
- Improved network section handling in Docker Compose files - network configuration is only created when networks are actually used

### Fixed
- Fixed variable validation logic in `ec2_deploy.sh` to correctly handle optional parameters
- Improved empty network detection to prevent creating unnecessary network sections in Compose files

### Documentation
- Updated README with examples showing both basic and full deployment scenarios
- Added clear documentation for optional parameters and their formats

## [1.0.1] - 2025-XX-XX
### Added
- Initial support for `COMPOSE_VOLUMES` parameter

### Changed
- Improved script error handling and logging

## [1.0.0] - 2025-XX-XX
### Added
- Initial release
- EC2 deployment support
- Docker Compose configuration generation
- Automatic Docker and Docker Compose installation
- Network cleanup functionality
- Docker image loading and deployment

### Features
- SSH-based deployment to EC2 instances
- Dynamic Docker Compose file generation
- Support for ports, networks, and volumes configuration
- Automatic formatting of Docker Compose files
- Cleanup of unused Docker networks
